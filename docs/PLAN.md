# Compiler Virtual Lab — Synthesized Architecture Plan (Gate A output)

Three independent proposals (algorithm-fidelity, architecture, ux-visualization) were scored by a
3-judge panel on correctness / extensibility / UX. **Winner: the algorithm-fidelity proposal**
(2 of 3 judges; scores 9–9.5 correctness, 8–9 extensibility, 8–8.5 UX), with specific ideas
grafted from the other two per the judges' recommendations.

## Tech stack
- **TypeScript 5.x strict** (+ `noUncheckedIndexedAccess`), **Vite** + **pnpm workspaces**
- **React 19** + **React Router** (deep links: `/syntax?algo=lalr1&step=42`)
- **Tailwind CSS v4** + shadcn-style components checked into the repo (Radix primitives for
  Tabs/Slider/Tooltip/Popover) — 21st.dev MCP unavailable (auth error), fallback per spec
- **CodeMirror 6** (`@uiw/react-codemirror` + `@codemirror/lang-cpp`) — decoration API drives
  step-synchronized source highlighting; far smaller than Monaco
- **Graph layout: elkjs** (ELK layered, in a worker) rendered via **React Flow** (`@xyflow/react`)
  for automata / GOTO graphs / CFGs; **d3-hierarchy** (tidy tree) for parse trees / ASTs / call
  trees; seeded pre-settled layout for the undirected interference graph
- **Zustand** store (one immutable `Compilation`), **Comlink** worker for compilation + heavy
  table constructions, **Vitest** + **fast-check** for tests
- **No parser generators, no automata libraries** — every algorithm hand-implemented to the
  Dragon Book (2nd ed.); that is the product.

## State model — event-sourced traces (the core contract)
Algorithms are **pure generators yielding typed JSON events**; the UI replays a **pure reducer**
over them. No per-step snapshots (LR(1) traces reach 10⁴–10⁵ events); instead keyframes every
~50 events give O(1) next/prev and fast `stateAt(i)` for jump-to-step.

```ts
type Steps<E, R> = Generator<[E, StepMeta], R, void>;      // algorithm shape
type Reducer<S, E> = (state: S, event: E) => S;            // pure, immutable
interface StepMeta {
  cite: Citation;              // MANDATORY Dragon Book citation (§, Fig/Algo, rule text)
  prose: string;               // human explanation of THIS step
  level: "macro" | "micro";    // play() at macro level skips micro groups
  groupId?: string; section?: string;   // scrubber tick-marks + Shift+arrow section nav
  srcSpans?: SourceSpan[]; irRefs?: IrRef[];  // provenance → editor/artifact highlighting
}
interface Trace<S, E> { steps; initial; length; stateAt(i): S; final(): S; findIndex(pred, from?): number }
```
**Replay invariant (CI-enforced for every algorithm):** folding all events through the reducer
must deep-equal the algorithm's returned artifact — "mutated without emitting" cannot survive CI.
Traces are deterministic (BFS worklists in grammar order) so state numbering reproduces the book's.
Hard `maxEvents` cap with a `truncated` flag surfaced as a UI banner; worker LRU-caches ~3 traces.

## Module boundaries (pnpm workspace, strict dependency direction)
```
packages/trace   — recorder/replay abstraction (zero deps, no DOM)
packages/core    — the compiler: common/ csubset/ lex/ grammar/ ast/ sem/ ir/ opt/ codegen/ interp/
                   pure TS, tsconfig lib ES2022 only (no dom); tested under Vitest node env
packages/app     — React app: components/ graphs/ editor/ store/ worker/ routes/ examples/
```
`core/csubset/` is the **single source of truth** for token specs (regex ASTs), the teaching
grammar(s), and AST node types. Contracts between phases are JSON-serializable artifacts with
backward provenance ids (instr → astNodeId → tokenIndex → span):
`TokenStream → Ast → SemanticInfo → TacProgram (quads canonical; triples/indirect derived views)
→ OptimizedProgram (per-pass snapshots + CFG) → AsmProgram`.
Contracts are frozen once phase work fans out; changes require explicit review (ADR note).

## Pipeline honesty (the critical design decision)
The pipeline's real parse **is** the traced **LALR(1) machine generated by our own table
constructor** from the C-subset grammar (crafted genuinely LALR(1): stratified expression
grammar; no typedefs/casts). Dangling-else is surfaced as a real shift/reduce conflict
resolved-by-shift with the §4.8.2 explanation. LL(1)/recursive-descent run on the traced,
algorithmically transformed grammar (left-recursion elimination Algo 4.19, left factoring
Algo 4.21 — shown as their own step traces). LR(0)/SLR on the full grammar surface their genuine
conflicts as educational content. Dragon Book study grammars (4.28, 4.1, 4.55) are additionally
selectable to reproduce the book's published tables exactly. Only the LALR parse feeds downstream.

Canonical LR(1) on the full C grammar gets an educational state cap ("built N states — this is
why LALR exists") instead of freezing the tab.

## UI structure
Routes: `/` overview, `/lex`, `/syntax`, `/semantic`, `/ir`, `/opt`, `/codegen` with
`?algo=&step=&pass=` deep links (same source hash ⇒ deterministic recompile ⇒ seek to step).
Every phase = `[Artifact visualization | TracePanel]`; one shared `<StepControls/>`
(prev/next/play/pause/reset, speed, macro/micro filter over ONE recorded trace, scrubber with
named section ticks, per-algorithm "jump to…" menu: next iteration / next conflict / next new
state / next error) + `<ExplainCard/>` with prose + `<CitationBadge/>`. Keyboard ←/→/space,
Shift+arrow section jumps. Explicit **Compile** button; edits mark views stale, never surprise-recompile.

**Layout stability rule (shared-viz policy):** compute the final graph layout once (ELK,
memoized by graph hash, off-thread), then only reveal/highlight per step — never animate layout,
only emphasis. Accessibility: aria-live polite step announcements, ≥44px transport controls,
`prefers-reduced-motion` fallback, shape-not-color coding (double-ring accept states, patterned
conflict cells). Errors are pedagogical stopping points: playback runs to the error step and
stops with a rule/span/expected-vs-found card. Big ACTION/GOTO tables virtualized.

## Testing strategy (5 layers)
1. **Textbook goldens**: `(a|b)*abb` → Fig 3.34 NFA / Fig 3.36–3.37 subset construction /
   minimized DFA; Grammar 4.28 FIRST/FOLLOW + Fig 4.17 LL(1) table; Grammar 4.1 → Fig 4.31
   LR(0) collection + Fig 4.37 SLR table + Fig 4.38 parse trace of `id*id+id`; Grammar 4.55 →
   LR(1) item sets + LALR merging + Fig 4.42/4.43; reaching definitions per §9.2 examples.
2. **Replay invariants** (every algorithm, automatic): reduce(all events) ≡ returned artifact;
   keyframe `stateAt` ≡ full replay; determinism; per-vocabulary domain invariants.
3. **Property-based oracles** (fast-check): NFA ≡ DFA ≡ minimized DFA language equivalence;
   all five parsers agree on membership; optimizer soundness via TAC interpreter before/after;
   asm interpreter ≡ TAC interpreter; allocator checker (no two live values share a register).
4. **Pipeline integration**: acceptance sample (function + loop + if/else) snapshot-tested
   end-to-end; error-path fixtures with message/span/cited rule.
5. **UI**: StepControls/stepper component tests; Playwright smoke across all phases.

## Build order (Gate B)
1. **Platform first (stable contract):** workspace scaffold, `trace` package + invariants,
   `core/common` + `core/csubset` + phase artifact contracts, app shell (routes, theme, store,
   worker, StepControls/TracePanel, editor, examples, shared graph/tree/table/diff primitives).
2. **Parallel phase agents** (disjoint folders, build against contracts + fixtures):
   lex · syntax-LL(FF/LL1/RD/transforms) · syntax-LR(LR0/SLR/LR1/LALR + pipeline parser) ·
   semantic · ir · opt · codegen — each lands core algorithms + reducers + golden tests + its route UI.
3. **Integration:** wire `compile.ts` end-to-end, overview page, cross-phase provenance.
